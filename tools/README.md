# Проверка сайта из GitHub Actions

`inspect_bgmu_source.py` читает публичную стартовую страницу `bgmu-time.ru`
и её JavaScript-модули. Отчёт содержит время проверки, HTTP-ошибки, список
полученных файлов с SHA-256 и строки, похожие на адреса API. Адреса API
в отчёте — кандидаты из исходников, а не подтверждённые рабочие запросы.

Стандартный Linux runner GitHub Actions для публичного репозитория бесплатен.
Workflow `.github/workflows/inspect-bgmu-source.yml` запускается при изменении
сборщика/workflow в ветке `codex/bgmu-source-inspection`. Результат возвращается
коммитом в эту же диагностическую ветку. Это позволяет прочитать его обычным
`git fetch`, когда GitHub API недоступен. Коммит отчёта повторный запуск не
вызывает. Workflow нужны разрешения `contents: write`.

По умолчанию используется обычное соединение runner. Если сайт ограничивает
его IP, в Settings → Secrets and variables → Actions можно добавить repository
secret `BGMU_PROXY_URL` с полным URL HTTP/HTTPS-прокси. Его значение читается
из окружения процесса, не передаётся аргументом команды и не записывается в
отчёт. Фактическая доступность сайта и прокси устанавливается только запуском.

Исходники сайта в `source-inspection/` — временные материалы разработки.
Диагностика не создаёт базу расписания и не подключает кэш к Telegram-боту.
Сборщик не входит в рабочий процесс получения расписания пользователями.

Локальный запуск на хостинге с доступом к сайту:

```bash
python3 tools/inspect_bgmu_source.py --output /tmp/bgmu-source-inspection
```

Проверка TLS включена. Сборщик ограничен доменами сайта, числом файлов,
размером ответов и общим временем выполнения; JavaScript только читается,
а не исполняется.
